# Atsi AI Hub — Architecture des agents V0.3

## Objectif

Introduire des agents configurables, persistants et traçables
en conservant l'architecture technique de la V0.2.

## Composants existants

- Angular : administration et pilotage
- NestJS : API et contrôle des accès
- PostgreSQL : stockage des données
- Redis / BullMQ : file d'exécution
- Worker TypeScript : traitement des tâches

## Modèle d'agent

Chaque agent possède :

- id : identifiant UUID
- key : identifiant technique unique
- name : nom affiché
- description : description fonctionnelle
- type : catégorie métier
- enabled : activation de l'agent
- config : paramètres JSON
- configVersion : version de configuration
- capabilities : capacités autorisées
- requiresApproval : politique de validation
- createdAt : date de création
- updatedAt : date de modification

Les clés techniques restent stables après création.

## Catégories initiales

- system : agents techniques et démonstration
- employment : agents liés à l'emploi
- portfolio : agents liés au portfolio

## Agents prévus

### demo-agent

Agent de démonstration conservé pour les tests.

Catégorie : system

### emploi-agent

Premier agent métier.

Catégorie : employment

Fonctions initiales envisagées :

- Organisation des candidatures
- Analyse structurée d'offres
- Préparation de synthèses
- Préparation de brouillons à valider

Aucune candidature ne sera envoyée automatiquement.

### portfolio-agent

Agent prévu pour une version ultérieure.

Catégorie : portfolio

## Configuration

La configuration est stockée en JSONB dans PostgreSQL.

Toute modification augmente configVersion.

Une exécution conserve un instantané de la configuration
utilisée au moment de son lancement.

Les secrets ne sont jamais stockés dans les configurations
JSON ni dans les résultats d'exécution.

## Exécutions

La table agent_runs existante reste conservée.

Une migration ultérieure ajoutera :

- une référence optionnelle vers la définition d'agent
- la version de configuration utilisée
- un instantané des paramètres non sensibles

Les anciennes exécutions restent consultables.

## Worker

La file BullMQ atsi-agent-tasks est conservée.

Le worker sélectionnera les traitements à partir
d'un registre de types de tâches explicitement autorisés.

Aucune exécution arbitraire de code ou de commandes
système ne sera autorisée par les configurations.

## Sécurité

- API administrateur protégée
- Validation des configurations côté serveur
- Capacités limitées par une liste autorisée
- Validation humaine pour les actions sensibles
- Aucun envoi automatique de candidature
- Aucun secret dans les journaux
- Aucune exposition publique des services internes

## Compatibilité

Le demo-agent V0.2 doit continuer à fonctionner.

Les migrations devront préserver les données existantes.

Les changements seront testés avant leur application
aux services en cours d'exécution.

## Hors périmètre V0.3

- Orchestration multi-agents avancée
- Exécution de scripts arbitraires
- Actions externes autonomes non autorisées
- Déploiement de modèles IA lourds sur le NAS
