# ATSI AI Hub — Archivage des candidatures

## 1. Objectif

Conserver un historique exploitable des candidatures
tout en limitant l'accumulation de données dans PostgreSQL.

Le système doit permettre :
- le suivi des candidatures ;
- la génération d'archives annuelles ;
- la consultation des bilans ;
- une purge contrôlée après validation humaine.

Ce document décrit une fonctionnalité future.
Aucune purge automatique n'est activée en V0.3.

## 2. Politique de conservation

### Candidatures

- Conservation minimale : 12 mois après la dernière activité.
- Les candidatures actives ne sont pas éligibles à la purge.
- Toute nouvelle activité repousse la date d'éligibilité.
- Les candidatures archivées restent consultables
  via les exports conservés.

### Journaux techniques

- Durée de conservation cible : 90 jours.
- Conservation prolongée possible pour les diagnostics importants.
- Aucune purge technique automatique en V0.3.

### Archives

- Conservation longue durée sur le NAS.
- Suppression des archives uniquement sur décision humaine.
- Vérification de l'intégrité des fichiers.

## 3. Archivage annuel

Une tâche planifiée prépare chaque année :

1. Un audit des candidatures.
2. La liste des dossiers éligibles.
3. Un rapport PDF.
4. Un export structuré CSV ou JSON.
5. Un manifeste avec empreintes SHA-256.
6. Une notification administrateur.

La génération des archives ne déclenche aucune suppression.

## 4. Validation humaine

L'administrateur peut :

- consulter l'audit ;
- examiner les candidatures ;
- exclure certains dossiers ;
- reporter la purge ;
- approuver explicitement les dossiers sélectionnés.

Une absence de réponse ne constitue jamais une approbation.

## 5. Sécurité de la purge

Avant toute suppression :

- vérifier les droits administrateur ;
- vérifier l'intégrité des archives ;
- vérifier la présence d'une sauvegarde ;
- vérifier à nouveau l'éligibilité des candidatures ;
- exclure les dossiers actifs ou récemment modifiés ;
- enregistrer la décision humaine ;
- conserver une trace de l'opération.

En cas d'erreur ou d'archive manquante,
aucune nouvelle suppression ne doit être engagée.

Les opérations doivent être conçues pour permettre
une reprise contrôlée après interruption.

## 6. Interface Angular envisagée

Rubrique : Archives & Audits.

Onglets :
- À examiner
- Historique
- Archives
- Paramètres

Chaque audit présente :
- son année ;
- son périmètre ;
- son statut ;
- les candidatures analysées ;
- les candidatures éligibles ;
- les candidatures exclues ;
- les fichiers d'archive ;
- les décisions administrateur.

## 7. Architecture future

Composants envisagés :

- archive_audits
- archive_audit_items
- archive_artifacts
- archive_approvals
- archive_purge_operations

Services envisagés :

- ArchiveAuditService
- ArchiveApprovalService
- ArchivePurgeWorker

Ces noms sont provisoires et ne constituent
pas des composants déjà implémentés.
